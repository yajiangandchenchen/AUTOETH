# Shared customer contract: Struct member identity and default presence

Struct `items`, `member_ids` and `member_present` have equal lengths, each equal to the schema member count. Their positions follow MemberSpec declaration order. At position i, `member_ids[i] == MemberSpec.node`. Two members may reference the same node; keep both positions. Do not merge or reorder them by node ID.

MemberSpec.dataId specifies the member's TLV wire tag. It does not replace member_ids or sort the Value vectors. An absent optional member keeps its fixed position and member_present=0. Its unused items entry is not encoded. Existing type, default, missing-member and resource rules remain.

If an entire required member is absent on the wire and a complete legal receptionDefault is allowed by the existing source/parent rules, successful decode stores that complete default Value at the declared position and sets member_present=1. This denotes a complete available required logical value. It does not claim that bytes were physically present on the wire.

An absent optional remains member_present=0 even if an inactive/default item exists. A required whole member without a default fails MissingRequired10. A partially present scalar/member/prefix follows ParentBounds7 or the applicable existing error; do not splice partial wire bytes with a default. Fixed-array missingElementDefaults apply to complete missing positions; arrays do not have Struct member_present vectors.

Native construction, measure/encode/decode and configured Classic typed projection use the same order and identity. Decode commits the complete vectors atomically. No field, enum, source wire format or API signature is added.
