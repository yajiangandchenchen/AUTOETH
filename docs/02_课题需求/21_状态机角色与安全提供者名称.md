# Shared role SM configuration and exact provider binding

This increment fixes existing configuration construction, without loading a provider implementation or adding a C enum.

## Role defaults require real configuration

The event/field default ON is a role setting; it does not create a window or thresholds. An event/field use that actually requires SM must have a complete legal `state_machine` object. If it is absent, reject with InvalidConfig during configuration, before publication, Check or Protect. Do not use an all-zero object or fake VALID state.

RPC defaults OFF and may omit the object. An explicitly provided complete object enables its SM use. Pure/offline operations retain their explicit operation and original Init contract. Existing unprotected roles remain their declared unprotected roles.

The existing `disable_check` behavior skips Check and SM and reports unchecked status without a business safety-release guarantee. A supplied SM object must still be complete/legal even when one particular use skips it. If a channel is shared across roles, validate every actual SM-requiring use; a different RPC use's default OFF does not satisfy an event's required configuration.

No new enable/disable field is introduced here. Keep the complete existing SM fields, ranges, source/native distinctions, windows, flags and Init transitions.

## Endpoint provider-name field

| Exact Native member | Default and role |
|---|---|
| `EndpointConfig::security_provider` | Owning `std::string`, default empty. |
| JSON `security_provider` | Same exact name string, conditionally required only when `requires_security=true`. |

With requires_security true, the field is required and nonempty, and must exactly match `security.providers[].name`. Do not select the first, last, only or similarly spelled provider. Duplicate, unknown or missing names fail in the phase where they are decidable.

With requires_security false, JSON forbids this key, including an empty value. The Native aggregate always has the member, so its value must instead be empty. Do not demand that a C++ aggregate member be absent.

Before start, the caller must use the existing binding API to bind an actual same-name `std::shared_ptr<SecurityProvider>`. A declaration/name is not that binding. Missing actual bindings fail in create/start as applicable before any socket/availability is established. Preserve whole-start transaction and rollback behavior; an unbound dependent endpoint cannot first publish success.

This binding-existence preflight does not replace the later real Pending/Ready/Failed/Expired provider gates or begin/cancel, asynchronous/synchronous completion, token and generation rules. Do not confuse a bound provider with a completed security association.

JSON does not load code, credentials or certificates. A name match or a controlled test callback is not evidence of TLS or cryptography. Existing source prototype, parameter type and provider API boundaries remain.
