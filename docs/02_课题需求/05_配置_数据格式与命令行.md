# SUPPLIED CUSTOMER DESIGN/API: configuration,schema,program andfile protocols

No private test corpus ororacle isprovided. Examples are ordinary customer configuration/businessdata;theirwire implementation andtestingmustbeindependent.

## customer contract External JSON and public Native values

All configuration documents are UTF8 JSON with integer schema_version1. Unknown/duplicate keys, malformed Unicode escapes,nonintegral/out-of-range numbers,invalid enum values,unresolved/duplicate references and wrong-role combinations fail before sockets/availability/Protect. Integer conversion is lexical and exact,not via double. customer contract defines exact ConfigDetail codes,validation precedence and optional owning ConfigDiagnostic output;its failure report is separate from unchanged configuration output. Document loaders bound bytes/nodes/depth before recursive ownership;all successful config/schema objects own their input strings/defaults. Relative file references resolve against the containing file's directory; configuration is restart-only. No implicit environment secret,network fetch or global configuration search is used.

RuntimeConfig publicly contains the customer contract root fields with matching snake_case names and owning C++14 containers: schema_version:uint32_t,node_name:std::string,client_id:uint16_t,ResourceConfig resources,SchedulingConfig scheduling,CorrelationConfig correlation,vector<InterfaceConfig> interfaces,vector<EndpointConfig> endpoints,vector<SchemaSpec> schemas,vector<ProvidedServiceConfig> provided_services,vector<RequestedServiceConfig> requested_services,vector<E2eChannelConfig> e2e_channels,SecurityConfig security,CompatibilityConfig compatibility,CaptureConfig capture. Default construction is empty/invalid until populated or loaded. Programmatic provider objects are described below and are not parsed from JSON as fake implementations.

A schema reference is exactly an object {file:string} or a complete inline SchemaSpec. A schema file has {schema_version:1,schemas:[SchemaSpec...]}. SchemaSpec fields are name:string,root:uint32 nonzero,role:event/field/methodRequest/methodResponse,argumentSet:bool,payloadByteOrder:Big/Little,tlvStaticLengthBytes:0/1/2/4,dynamicTaggedLength:bool,defaultAlignmentBits:8/16/32/64/128/256,nodes:[NodeSpec]. Names are unique across all imports. Node IDs are local nonzero uint32 values,unique in that SchemaSpec. Only reachable,acyclic nodes are permitted; a node reference cannot cross schema documents by accidental numeric equality.

NodeSpec has id,kind and the exact customer contract kind-specific fields. Primitive kind is Bool/Unsigned/Signed/Float32Bits/Float64Bits with legal widthBits. Struct has ordered members,lengthBytes,tagged. Each member has name,node,optional,optional dataId and optional receptionDefault. Array has element and exactly fixedCount or maxReceiveCount,lengthBytes and only fixed arrays may provide missingElementDefaults. ByteArray uses dynamic maxReceiveCount/lengthBytes or explicitly fixedCount. String has encoding,lengthBytes,maxWireBytes and optional fixedWireBytes/maxUnicodeScalars. Union has selectorWidthBytes,variants[{selector,node}],lengthBytes and optional nonemptyPayloadExtentBytes. A kind cannot accept another kind's keys. customer contract defines all bounds/default/skip/Unicode/wire behavior; fixtures with logical inline child descriptions are not this external node-reference grammar.

argumentSet=true is allowed only for a method root Struct with lengthBytes0 and no extra root prefix. Its members are the actual ordered operation arguments. A Struct passed as one argument is a child of that root and keeps its own configured struct-length behavior. Event/field roots have argumentSet=false. Top values/defaults must match this distinction; errors cannot be hidden by automatic wrap/unwrap of arbitrary nested structures.

The public Value is an owning C++14 discriminated aggregate. ValueKind is Bool,Unsigned,Signed,Float32Bits,Float64Bits,Text,ByteArray,Struct,Array,Union. Public fields are kind:ValueKind,boolean_value:bool,unsigned_value:uint64_t,signed_value:int64_t,float32_bits:uint32_t,float64_bits:uint64_t,text_utf8:std::string,bytes:vector<uint8_t>,items:vector<Value>,member_ids:vector<uint32_t>,member_present:vector<uint8_t>,selector:uint32_t. Only the active kind is serialized. Struct items/member_ids/member_present have equal lengths equal to the schema member count, in MemberSpec declaration order. member_ids[i] equals MemberSpec.node; repeated node references remain independent positions. Presence bytes are 0/1. A complete allowed required default produces member_present=1; an absent optional remains 0. Array uses items;Union has0 items for selector0 and exactly1 for a selected nonzero variant. All C++ members have normal live storage;no inactive native union is read. Caller mutation/concurrent mutation during a call is forbidden. Unused fields do not become hidden wire bytes. Decode builds a fresh temporary and commits only on success.

Value JSON follows the selected schema: ordinary booleans/integers/text,object members by exact schema name,arrays as JSON arrays;ByteArray is {hex:even-hex-string};float bits are {ieee754_hex:8-or16-hex-digits};Union is {selector:exact-integer,value:typed-value} or {selector:0} without value. Optional absent members stay absent;all other unknown value members reject. Strings are JSON Unicode values;customer contract terminated text rules apply only after JSON decoding. Pure ByteArray never becomes Text.

## customer contract Exact Runtime nested fields and role checks

InterfaceConfig fields: id,name,local_address,address_family,optional interface_index,scope_id,sd_port,sd_multicast_address,loopback_enabled,multicast_hops. id is a unique local string;name resolves an actual OS interface. Missing interface_index resolves by name and records the real result;provided index must match. scope_id defaults0 and is required where an IPv6 scoped address needs it. IP family/address syntax,unicast local address and proper-family multicast SD address are checked. No physical link/ARP/IP-assignment success is fabricated.

EndpointConfig fields: id,interface,transport,local_port and role-specific keys. TCP requires tcp_role listen/connect,tcp_no_delay optional defaulttrue,and optional fixed remote_address/remote_port pair. UDP permits tp_strategy,max_segment_payload_bytes,rx_timeout_ns,changed_overlap_reject,max_udp_datagram_bytes,udp_bundle_delay_ns,max_bundle_messages,and optional remote pair/multicast_endpoint. The remote pair is all-or-none;multicast_endpoint=true requires a UDP multicast remote. Inapplicable TCP/UDP keys reject. A connect endpoint without fixed remote uses a qualified SD endpoint at connection establishment. customer contract fixes the exact UDP defaults/configured capacity/IP fragmentation/FIFO/sealing/failure behavior. All Native messages retain full16B framing;Classic extra header mode is a separate customer contract map.

ProvidedServiceConfig is its service descriptor plus endpoints:[endpoint-id],auto_available and server_timing. RequestedServiceConfig is its declared remote descriptor plus query_handle,endpoints,query,auto_require,capabilities and client_timing. Descriptor fields are name,service_id,instance_id,major,minor,methods,events,fields,event_groups. Query fields are service_id,instance_id,major,minor,minor_match and transports;wildcards are the literal string ANY rather than an Exact value inferred from all-ones. minor_match=EXACT is the sample;the already selected explicit version criteria remain selectable and cannot be guessed from a missing numeric value. Client eventgroup descriptors do not carry the provider's server_multicast endpoint reference or threshold policy.

A method has method_id, name, kind, request_schema, optional response_schema, transports:[UDP/TCP], optional udp_segment, application_errors:[1..63], optional detailed_errors:[{application_error,schema}] and exactly e2e:channel-id or unprotected:true. DetailedErrorSpec uses an owning exact schema-name string in Native configuration too; the default mapping is empty and detailed schemas use the existing methodResponse role. A FF has no response/error-waiting contract. udp_segment=true is legal only with UDP selected and a configured endpoint TP strategy. A duplicate element ID,empty transport list,inapplicable field or unsupported schema role fails. customer contract's earlier singular transport description means this exact declared nonempty list;MethodRef chooses one available declared transport.

Events have event_id,name,schema,group_ids,transports,e2e,pure_event. Fields have name,schema,getter,setter,notifier,readable,writable,notifiable,initial_value. Required elements must exist. Getter response/setter request/setter response have exactly one typed field-value argument whose child shape matches the field schema;notifier has that same shape. Runtime get_field/set_field wraps/unwraps only this declared one-argument mapping,then returns the field Value to the SDK. It does not mistake an application revision metadata record for the field type. Sample Calibration field is the calibration value;ApplyCalibration's separate RPC response contains revision plus calibration.

Provider event_groups have group_id,event_ids,ttl_seconds,multicast_threshold and optional server_multicast endpoint. Consumer groups have only group_id,event_ids and requested ttl_seconds. Unknown group references/duplicate IDs fail. Provider threshold>0 requires its actual UDP multicast endpoint;consumer obtains any dynamic multicast destination from a valid ACK. Field initial value must type-check before start. Capability records use approved customer contract raw-byte/missing/empty distinctions and do not borrow Unicode string semantics.

E2eChannelConfig fields are channel_id,profile,configuration_surface,config,optional legacy_compatibility/behavior/source_id/state_machine/disable_check. SourceC means exactly the original named Config fields in c-source,using bit units. NativeWide is available only for08/08m and uses customer contract's named uint64 fields. Unknown extra fields reject.01/02 explicitly require legacy_compatibility=true;behavior is R4_2 or PRE_R4_2. Method source_id is a Native channel input,not an added source Config member. Every logical protected element has a distinct configured DataID in the sample;request/response of one method share that operation's agreed DataID. No global producer safety allocation or certification is claimed. Normal registration rejects reserved service0/FFFE/FFFF,instance0/FFFF,method0/7FFF,event8000/FFFF,andgroup0/FFFF;the configured native ranges are method1..7FFE,event8001..FFFE,instance/group1..FFFE. FF00..FF5F OEM/Tier1/ECU-private service purposes are not selected normal registrations. Raw codecs still preserve/display these fields and the specialFFFF SD/magic forms;SoAd's independent32-bit HeaderID domain is not reduced to normal service registrations.

ResourceConfig adds max_e2e_rx_contexts=4096,max_udp_sockets=128,max_multicast_memberships=256,all positive uint32,for these actual runtime-owned registries/socket/group objects. Existing customer contract budgets remain. Inability to reserve a new context/socket/membership is explicit Resource;accepted unrelated state is not evicted. customer contract now defines the measurable data-plane byte-capacity ledger precisely. Raw transport metadata/window byte arrays share it;C++ container/index bookkeeping is separately observed/bounded by declared counts,not falsely included as a precise RSS total. Opaque callback/provider captured graphs and caller-retained metadata are excluded/caller responsibility. Owned payload copies/staging and snapshot-held byte tokens remain charged until their true last owner. Native maximum08/08m pure API buffers still use the full domains. A maximum nonmethod08 frame needs rawLength+8 bytes;method08m needs rawLength+16. The large-domain example max_frame_bytes536870944 accommodates both;536870920 alone would fit the former but not the latter. This arithmetic clarification does not alter raw C/wide length domains or existing numeric CRC oracles.

SecurityConfig JSON has providers:[{name:string}],with no executable provider/credential material. requires_security on an endpoint defaultsfalse. Programmatic RuntimeConfig binds each name to an owning shared_ptr<SecurityProvider>. Its interface is Status begin(const SecurityRequest&,SecurityCompletion,uint64_t& token) noexcept and void cancel(uint64_t token) noexcept. SecurityRequest owns endpoint/peer/connection generation;completion is an owning callback of token plus Pending/Ready/Failed/Expired. Callbacks from any thread enqueue a generation-qualified control event and never reenter IO. Missing provider fails before start;Pending waits,Ready enables only the actual qualified route,Failed/Expired clear readiness/subscriptions and cause eligible NACK/local failure. A controlled provider proves this gate only,not TLS/ARP/cryptographic strength. Default examples are explicitly unsecured.

## customer contract Useful application behavior and exact commands

Commands below are planned future real installed invocations,not results. Paths are portable after cd into installed share/autoeth/examples. Server starts with:
autoethd --config server.json --dataset vehicle-dataset.hex --dataset-format hex --event-period-ns 100000000

Initial demo sensor snapshot is revision1,speed_centi1234,temperature_deci250,flags1,label demo. These are explicit sample values. Initial Calibration is speed_limit_centi9000,gain_milli1000,label baseline. ApplyCalibration and the field setter validate speed_limit0..30000,gain1..2000,nonempty label within schema bounds. Application error1 is range,2 empty label,3 unavailable commit/fanout resources;wire values are20/21/22hex. All remain distinct from transport/E2E/local validation errors.

A successful calibration operation reserves reply/notifier resources,then commits value and checked revision+1 once in the owner loop. Its field notifier sends the field value only;ApplyCalibration's RPC response contains revision plus value. A rejected operation returns the previous complete value/state and leaves revision unchanged. RESPONSE80 application-error parameters are still encoded/decoded as configured. Later IO failure does not roll back committed business state or replay the side effect.

RecordCommand validates its declared schema/opcode1..255 and stores sequence/opcode/payload in a bounded128-entry in-memory business ring plus counters. It is explicit unprotected FF,has no RPC response and makes no durable logging/exactly-once promise. The ring policy overwrites the oldest completed record,not runtime accepted-transaction state. Its success is a received business fact only when actual server observations exist.

Client commands: discover;read-snapshot;read-bulk --offset 0 --length 32 --transport TCP (or UDP);apply-calibration --value calibration-value.json;record-command --value record-command-value.json;field-get --field Calibration;field-set --field Calibration --value calibration-value.json;subscribe --group 1 or2 --event-count N --duration-ns T. Each takes --config client.json (client-two.json for the second independent peer),--service vehicle and optional --timeout-ns,default1000000000. Method/transport/schema selection must match the declared descriptor;the CLI never changes profiles to get a successful response. Native field convenience uses a flat field Value;ApplyCalibration wraps its one declared argument.

ReadSnapshot after successful calibration reports revision2;ReadBulk offset0/length32 returns00..1F and total_size1024. Successful apply/field-set value N produces speed_limit10000,gain1000,label N. CLI exit0 is its stated successful contract;2argument/config,3NoService/Timeout,4RemoteApplication,5protocol/E2E,6IO/Resource,130interrupt. A FF local send completion is printed as local acceptance/progress,not server execution.

VehicleEvent is a pure periodic event,no invented subscription initial value. Calibration notifier has source-required initial wire notification after ACK. The configured field/event SM starts through real Init;an initial good notification may be INIT and not released to the business until VALID. The client prints diagnostic/SM observations separately. External periodic publication takes a real immutable business snapshot;its revision records what was captured,not a promise that asynchronous events are globally linearized after every separate RPC. An integration check drains/qualifies actual events and does not impose an unsupported cross-thread freshness order.

Applications own their signal handling;SDK installs no process-global signal handlers. OnSIGINT/SIGTERM,the program stops new publication,requests/drains its own Runtime,joins its own work and reports actual StopOffer/StopSubscribe send outcomes. Callback-safe request_stop and external stop/join remain customer contract. Server never joins its loop inside a callback.

## customer contract Operations, state files and visible output commit

autoethctl commands are validate-config,validate-schema,decode-frame,inspect-capture,e2e-protect,e2e-check,inspect-state. decode-frame takes an explicit file/hex and optional declared schema/channel;header decoding alone is not an authenticated or checked application result. inspect-capture reads only the explicitly supplied own-traffic file. Offline E2E commands select --profile-config e2e-profiles.json --channel pNN,plus --state-in state.json or mutually exclusive --init-state;the latter calls the real profile Init,including the existing original P01/P02 ProtectInit/CheckInit interfaces (00385/p88,00390/p90,00387/p94,00391/p97),not an invented replacement factory. Protect requires --input;Check allows --input or --no-data. --input-format binary/hex defaultsbinary and is explicit when using the .hex input examples. Metadata/type/result/source options follow the actual selected method role. Map/SM calls are actual library operations as configured,not a lookup used instead of Check.

State JSON is {schema_version:1,profile:string,state_kind:protect/check/sm,state:{exact-source-fields}}. Raw status values are exact integers0..255;state shape/counter/window bounds follow its profile. The original P22 state field order is Counter thenStatus in C;JSON key order never changes the C aggregate. Optional SM state includes its real window values/top/counts,not a magic initialized VALID flag. Input state files are read-only.

An offline result publishes a new directory containing data.bin,state.json,result.json. Reserve/validate before Protect;stage in a unique same-parent temporary directory;write/close all files,then rename the whole directory to the requested non-existing output. Existing targets reject without overwrite. Failure before rename leaves no published target and reports any recoverable temporary path;after successful rename a stdout/log failure cannot pretend the output was rolled back. This is a visible atomic directory publication under the host filesystem contract;no power-loss durability/fsync guarantee is claimed. No input state file is replaced.

Own-traffic capture is UTF8 JSON Lines,format autoeth-own-wire-jsonl/schema_version1. Records have sequence,monotonic_ns,node,record_kind,interface/endpoint,connection_generation,direction,original_bytes,captured_bytes,truncated,data_hex and typed event fields. record_kind distinguishes FrameBuilt,KernelWrite,KernelDatagramAccepted,RxChunk,RxFrame,Terminal,Loss. A built/owned frame is not a kernel or peer fact. A footer records complete=true,record/lost counts;missing footer or partial last line is incomplete capture. Parsing stops at a malformed interior record with precise offset;valid prior records remain diagnostic evidence,not a fabricated complete replay. Ring overflow increments lostRecords. Only full nontruncated actual wire records can support a full-byte network oracle.

The default fixed-endpoint quarantine is60s;short-time happy-path RPC tests use an explicit fresh-context configuration with the approved customer contract operator assumption recorded. The fresh-context example files set this existing flag true and are not evidence of measured packet lifetime. Default false examples retain the real wait;CLI overall timeout must encompass it. SD/control readiness and RPC response qualification remain distinct;no default refusal is relabeled happy-path success.


Legacy init is exact:ProtectInit sets Counter0. CheckInit sets LastValidCounter0,MaxDeltaCounter0,WaitForFirstDataTRUE,NewDataAvailableTRUE,LostData0,Status own NONEWDATA,SyncCounter0,NoNewOrRepeatedDataCounter0. P01 first Protect uses wire0 then incrementsmod15;P02 firstincrements to1 then writes. First valid Check keeps actual INITIAL04 and R4_2 mapping02;it is not silently faked OK. For legacy no-data the caller uses actual configured-length valid dummy storage and sets NewDataAvailableFALSE before Check;newer NULL/0 semantics do not replace that source interface. Normal calls set NewDataAvailable according to real current input.

Pure e2e-check is an actual raw check,not a runtime disable-check shortcut. Runtime channel disable_check is optional/defaultfalse,skips Check/SM only at the selected binding and reports unchecked66/no business safety release;sender Protect never bypasses. Method profiles are restricted to request_response canonical request/response roles,not event/FF. Offline raw operations preserve distinct return/raw/generic/SM fields. A completed check may publish a diagnostic bundle even when current data is unusable:legacy INITIAL R4_2,communication faults or no-data use exit5 with operation_completed=true,not a failed-to-run fiction. data.bin is explicitly labeled protected_output for successful Protect,checked_input for Check,or input_unchanged on rejected invocation;it is not application-release evidence. State input files remain unchanged.


The provided-service field notification_session_handling is optional INACTIVE/ACTIVE, default INACTIVE. Requested-service declarations do not select a remote server mode. Complete v1.3 types, name resolution, detail schema validation, UDP capacity, notification flow/commit and failure effects are in 13_错误返回_UDP传输与通知.md and 06_配置字段与默认值.md. ## v1.4 endpoint and usage validation

EndpointConfig has owning std::string security_provider, defaultempty, with the conditional same-name JSON field. requires_security=true needs the explicit nonempty exact provider name and real programmatic binding; false JSON forbids it while the Native field is empty. Do not infer the first/only provider. Validate at configuration/create/start before sockets/availability as applicable.

A role that uses SM needs a complete legal state_machine object. Event/field defaultON is not default numeric parameters; RPC defaultOFF may omit the object. Explicit objects stay fully validated even for a use that skips Check/SM. The full existing role and unchecked behavior is preserved.

max_segment_payload_bytes is an upper bound, not necessarily aligned. Use min before floor-to16 under 19_TP负载上限与对齐.md. The current complete validator and root Array/Union rules are in the other v1.4 contracts, with no new Codecs/NodeSpec keys.
