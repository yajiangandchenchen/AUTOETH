# Shared SD receiver refinements after v1.3

Apply this approved narrow overlay after the complete v1.3 contracts. Preserve all old inputs and frozen batches. The previous Q020 rules remain in force except for the explicit clarification below. Raw data, entry-reference handling and the global SD peer override are different roles.

## A valid global SD Endpoint is not removed by an invalid entry reference

A first-position, same-family, UDP, nonzero-port, valid unicast SD Endpoint Option 24/26 remains usable for its message-level reply destination and selected sender/receiver reboot relation even if a Find entry incorrectly references it. Ignore that entry's reference to the SD Endpoint. Do not make the otherwise valid global override disappear.

Run/index/extent safety checks still occur first. Ignoring the reference cannot hide an out-of-bounds run or an option whose actual extent cannot be located. This distinguishes source entry-reference ignore rules 00857/00859 from the global uses in 00549/00556.

For a complete, safely located SD Endpoint whose L4 is TCP, whose address is multicast, or whose other semantics are invalid for that global role, retain raw data and diagnostics, ignore the invalid global override and use the actual outer SD sender IP/port. It must not change reply/reboot identity, cause all other valid entries to be dropped or create a send to an unusable destination. This is an explicit LOCAL receiving rule.

A real message/extent/run structural failure retains the original whole-message safety result. Do not force unsafe data into the logical-ignore path. The existing port-zero global-override fallback and other first-position/family/count rules remain.

## Endpoint and multicast reserved fields on receipt

For an otherwise qualified required Option 04/06/14/16, a nonzero actual seven-bit reserved field in the option header or the later reserved eight-bit field is retained in raw data and diagnosed. Those reserved values alone do not reject the message or entry and acquire no new semantics.

Normal local sender options still set these reserved bits to zero. DF is a separate real flag; it is not part of this reserved-bit tolerance. Unknown DF/type, length, family, L4, address, port and conflict checks retain their own rules.

A newly generated ACK option is not required to copy an incoming option's reserved bits. That rule is separate from the approved exact Eventgroup Reserved12 echo in ACK/NACK entries.

## Invalid Subscribe Instance ID 0xFFFF

An otherwise reply-eligible invalid Subscribe with Instance ID 0xFFFF receives a NACK whose instance is exactly 0xFFFF and whose TTL is zero. Copy Counter/Reserved and the other required identity fields under the existing specific response rule. Do not register the service, publish success or trigger a field initial.

Retain the literal conflict with the general Eventgroup sender rule that an instance is not 0xFFFF. This invalid-input reply domain is APPROVED_HOST_MAPPING / UNSATISFIED_IN_LITERAL_GENERAL_SENDER_RULE; it is not simultaneous literal conformance and does not permit a valid service registration with instance 0xFFFF.

An unsafe, unidentifiable or otherwise non-reply-eligible entry gains no new reply permission. Multicast Subscribe ignore and the original no-error-loop/eligibility rules remain. Raw uint16 width is distinct from valid service registration.

These clauses fix common observable policy before dependent cases and implementation. They are not evidence of software repair, execution, product acceptance or a method advantage.
