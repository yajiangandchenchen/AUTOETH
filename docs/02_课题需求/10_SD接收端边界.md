# Shared customer contract: SD receiver roles and effective options

This document contains the complete approved Q020 receiving rules. It distinguishes raw width/structure, the normal sender, and the state engine. Preserve the original source language and the explicit host differences. The approved receiver rules do not establish target execution or literal conformance to contradictory general sender clauses.

## Eventgroup Reserved12 and Counter4

A（推荐）：raw decode保存真实12-bit Reserved及4-bit Counter，结构/宽度合法就不因Reserved非零全包或条目拒绝。正常本地新Subscribe/Stop生成Reserved0。Engine对其余条件合格的非零Reserved Subscribe接纳，并在ACK或因其他实际错误生成的NACK中逐bit回显该Subscribe的Reserved12；Counter独立复制。一般“发端Reserved置0”(00270)与具体ACK/NACK“Reserved相同”(00391/00394)在非零入站域冲突，明确采用具体复制规则并记录APPROVED_HOST_MAPPING / UNSATISFIED_IN_LITERAL_GENERAL_SENDER_RULE，不声称同时字面满足两条。未知/invalid entry的原ignore/NACK资格不因Reserved被改变。raw codec不是自动证明正常发端合规，原字节可显示/复现。

## Dynamic advertised port zero

A（推荐）：raw codec保留0/1/65535，不把STATIC peer端口1..65535或Native local0 ephemeral借成原始wire解析约束。Engine不把实际需要用于业务/组播目的地的广告port0当作可行动端点，不connect/send到0，也不解释为ephemeral。先应用下项明确ignore例外；仍被使用的04/06或14/16端口0为逻辑无效选项：Offer/StopOffer/Find等非Subscribe相应entry忽略，不提交其中半份endpoint/cache变化；Subscribe按既有可回复资格NACK且TTL0，无注册/初值；StopSubscribe忽略而不生造NACK；ACK作为failed ACK，不置AVAILABLE、不启用接收路由；NACK含不允许/无效使用选项也不当作成功ACK。其他有效entries继续处理。未引用、确实不需要且按00231已忽略的port0不使无关entry失败。
24/26是message-level SD Endpoint，不应entry引用；它若advertise port0，忽略该SD Endpoint并回退实际外层SD sender IP/port，当前消息其他有效entries不因此全丢。其原先第一位置/最多一个/族相符/不引用约束继续；不以port0重写reboot身份或回复到0。此“不可行动的0”及fallback是显式LOCAL动态接收选择，不称原uint16字段文字自带非零限制。

## Exact receiver order and exceptions

A（推荐）：保持正常sender按00583表发送，Find不发LB、客户端组播正常发04/06仍遵Q014；receiver单独采用下面明确顺序和特例，不把发端表直接扩成所有物理引用先拒绝。
a. 先校验整个message/entries/options实际extent、run索引和数量的安全范围；不可定位结构错误全包无前半提交。这里不是先拒绝所有未引用option的逻辑内容。
b. 按实际entry和已知服务/订阅角色分类引用选项。未知DF1、已知但该entry不允许且DF1、同type且完整option字节完全相同的冗余副本按源忽略；保留原始option数组和诊断，不篡改raw输出。未知DF0不能冒称“不需要”绕过失败。
c. 对00231明确“不需要”的选项，仅在真实角色能确定不需要时忽略，不把所有不允许的DF0类型都说成不需要。已批准Find LB特殊接收ignore继续。纯multicast、无field initial、无TCP事件需求的提供组可确定忽略不需要的client unicast endpoint。若有field初值或可靠事件，仍需要相应可用目标，不可借threshold1绕过。若角色分类需要读取字段，先做能安全读取的extent检查；不能安全判定时不可凭空归类成可忽略。
d. 对剩余effective引用应用允许类型/数量和实际required/support检查，然后验证其type-specific长度、族、L4/address/port以及冲突。无引用的逻辑无效普通option不污染其他entry；引用的invalid required option按原entry型ignore/NACK/failedACK处理。count0 run的无意义index继续忽略。
e. 00583 Config正常发送0..1；接收明确保留00844“两Configuration Options”特例：最多两个非同字节的Config，均逐option/逐record有序保留和处理，同名冲突items也全部进入能力匹配，不merge/map覆盖；不以一般same-type conflict先吞掉这个特例。不把两个不同Config假称合并成一个。第三个distinct Config仍按该entry型无效；完全同字节冗余先忽略。保留sender表与该receiver特例的字面差异/角色，不扩大其他cardinality。
f. Receiver同时支持原00323/00545允许的Subscribe/StopSubscribe客户端14/16组播声明，以及Q014允许的04/06 UDP clientMC。ACK14/16仍是server multicast角色，不能混同。按同一族、UDP、真实组播地址、非零可行动port、所需目标及effective cardinality检查；TCP multicast仍非法。正常sender继续采用Q014的04/06，不因新增原receiver容忍改变其发端字节。用source和host选择分别标识，不能因正常sender选择04/06就说receiver禁止原14/16。


## Per-entry outcome for a remaining used port-zero option

Apply the approved ignore exceptions before this table. A whole-message structural failure still causes no earlier entry commitment.

| Actual receiving role | Outcome |
|---|---|
| Offer / StopOffer / ordinary non-Subscribe entry with a used invalid option | Ignore that entry; do not commit half its endpoint/cache changes. Process other valid entries. |
| Subscribe with an otherwise reply-eligible invalid required option | NACK with TTL zero and the required copied identity, Reserved12 and Counter4; no registration, fanout or field initial. |
| StopSubscribe with the invalid used option | Ignore it; do not create a new NACK obligation or remove an unrelated valid relationship. |
| ACK with the invalid used multicast destination | Failed ACK; do not publish AVAILABLE or enable the receive route. |
| NACK with a prohibited/invalid used option | Do not treat it as a successful ACK or create availability. |
| Message-level SD Endpoint 24/26 advertising port zero | Ignore that override, retain the actual outer SD sender relation for reply/reboot processing, and continue other valid entries. |
| Unreferenced or genuinely unneeded option already ignored under the approved order | No unrelated entry failure solely from its port zero. |

Normal sender cardinality remains the source table. Effective receiver counting follows the exact exceptions above, including at most two distinct Configuration Options. Original raw options and records remain ordered and visible; this is not map merging or blanket cardinality expansion.
