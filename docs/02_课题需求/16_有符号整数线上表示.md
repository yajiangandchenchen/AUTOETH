# Shared customer contract: signed wire values and enum scope

For signed widths n=8, 16, 32 or 64, every representable signed value x uses the two's-complement unsigned bit pattern x modulo 2^n. Arrange that pattern according to the selected payload byte order. Preserve the existing signed value domains and public widths. Do not depend on an overflowing host signed conversion.

Float32Bits and Float64Bits retain their exact raw patterns, including NaN payloads. This contract adds no decimal floating-point normalization.

The public NodeSpec continues to use its existing Unsigned/Signed width grammar. It has no new enum descriptor, enum mapping or enum range key. Paired interface enum tables and underlying exact values may describe a wire-compatibility case. Unknown labels do not automatically create a codec rejection. Application-label interpretation or rejection must remain explicitly unresolved wherever the actual interface contract has not specified it; correct bytes alone do not establish that application-semantic compatibility.

The original compatibility matrix's X, blank, N/A, direction and conditional cells remain distinct. Source roles and complete counterpart interface definitions still determine applicability. This is common supplied representation policy, not a product result.
