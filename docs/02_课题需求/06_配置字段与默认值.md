# Supplied public configuration tables

These tables state the existing public JSON fields, limits and defaults, with the approved v1.3 additions. Unknown or duplicate keys reject. Parse integers exactly, validate roles and references, and use checked time and size arithmetic. Examples do not define missing ranges.

## ResourceConfig

| Field | Type and default | Domain and meaning |
|---|---|---|
| `max_frame_bytes` | uint64; 8388608 | At least 16; must fit host size_t and the SOME/IP Length32 geometry before allocation. |
| `max_owned_payload_bytes` | uint64; 268435456 | Positive; bounds measurable owned data-plane byte capacities, copies and staging, including transport metadata and window byte arrays. |
| `max_commands` | uint32; 4096 | Positive normal-command slots. Reserve required control capacity; the checked handle-capacity sum with max_active_rpcs must fit its advertised slot domain. |
| `max_active_rpcs` | uint32; 4096 | 1..65535; nonzero Session pool shared across methods in the declared namespace. Retired identities remain unavailable. |
| `max_tcp_connections` | uint32; 128 | Positive; real descriptor, readiness and I/O failure remain observable. |
| `max_tp_rx_contexts` | uint32; 128 | Positive; isolate FO and CP strategies. A bounded discard marker also occupies one context slot. |
| `max_visible_sd_instances` | uint32; 4096 | Positive; new admission cannot evict unrelated accepted state. |
| `max_server_subscriptions` | uint32; 4096 | Positive; actual server capacity failure NACKs the new attempt and preserves valid relationships. |
| `max_schema_nodes` | uint32; 4096 | Positive; bounds resolved nodes/descriptor indices and the declared structured-configuration parsing nodes. |
| `max_schema_depth` | uint32; 64 | Positive; references are acyclic. Bounds parser/schema/codec recursion; not a universal original wire-protocol depth limit. |
| `max_e2e_rx_contexts` | uint32; 4096 | Positive; real peer/client/element receive state and windows. No hidden idle eviction of accepted history. |
| `max_udp_sockets` | uint32; 128 | Positive; actual owned sockets, including dynamic multicast receivers. |
| `max_multicast_memberships` | uint32; 256 | Positive; actual group/interface joins. Failed admission rolls back only its own acquired resources. |
| `max_trace_records` | uint32; 4096 | Positive; bounded own diagnostic/capture ring. Lost and overwritten records remain observable. |
| `trace_payload_bytes` | uint64; 1048576 | Maximum raw bytes retained per record. Zero allows metadata-only capture; retain original/captured lengths and the truncated flag. |

Payload ownership tokens survive Runtime stop until their last byte-storage owner releases. This byte budget does not claim exact bounds on C++ objects, containers, configuration names, maps, control blocks, allocator overhead, kernel socket buffers, opaque callbacks/providers or caller-retained metadata snapshots. Available registry counts, flat capacities and element sizes are separate partial observations, not additive RSS accounting.

## SchedulingConfig

| Field | Type and default | Domain and meaning |
|---|---|---|
| `main_period_ns` | uint64; 1000000 | Positive monotonic scheduling period, with no hard real-time claim. |
| `shutdown_drain_ns` | uint64; 2000000000 | Checked duration; zero gives no grace period. Own cleanup/join and caller handler lifetime constraints still apply. |
| `transport_abort_cleanup_ns` | uint64; 1000000000 | Positive cleanup budget. An overdue cleanup retains actual transport/session resources instead of freeing identity early. |
| `connect_retry_ns` | uint64; 100000000 | Positive backoff for new connection work; no implicit replay of a side-effecting RPC. |
| `rpc_timeout_ns` | uint64; 1000000000 | Positive configured default. A per-call DurationNs includes queue/admission and checked addition to the actual clock. |

Server SD timing fields retain their exact names: `initial_delay_min_ns`, `initial_delay_max_ns`, `repetition_base_ns`, `repetitions` (0..10), `cyclic_offer_ns` (default zero), `request_response_min_ns`, `request_response_max_ns` and `ttl_seconds` (default three). Initial/response ranges default to zero..zero. Base zero, N zero and cyclic zero follow the fixed customer semantics. Check minimum<=maximum, exponentiation and deadlines.

Client fields are `initial_find_min_ns` / `initial_find_max_ns` (default zero), `repetition_base_ns` (zero), `repetitions` (zero), `request_response_min_ns` / `request_response_max_ns` (zero), `subscription_retry_delay_ns` (10000000), `subscription_retry_max` (zero, or explicit string `infinite`) and `subscription_ttl_seconds` (three). Validate retry delay and mode-specific key presence under the discovery/control contract. TTL wire integers fit 24 bits; zero has entry-specific Stop/NACK meaning and `0xFFFFFF` has its special lifetime. Classic retry 0..255 and 0.001..50 seconds retain their separate source mapping.

STATIC forbids virtual SD timing. ACTIVE/TTL_ONLY selection, HALF_CYCLE's positive C, RRD handling and the processing-time destination snapshot are specified in the current discovery/control and timing documents.

## CorrelationConfig

| Field | Type and default | Domain and meaning |
|---|---|---|
| `retirement_horizon_ns` | uint64; 60000000000 | 1000000..3600000000000 ns. Explicit LOCAL peer/network lifetime assumption; use the defined quiescence origin. |
| `fresh_context_asserted` | bool; false | Explicit operator assertion permitting the specified startup-wait skip. It is not measured latency, authentication or an unbounded replay proof. |

## CaptureConfig

| Field | Default and domain | Meaning |
|---|---|---|
| `enabled` | bool; false | Own-traffic capture request, never global raw network capture. |
| `output_path` | Absent, or explicit nonempty UTF8 path without NUL | Absent means no file publication. An explicit path selects the own capture file with observable I/O errors. Disabled capture does not write it. |
| Record/payload limits | ResourceConfig max_trace_records / trace_payload_bytes | One source of limits; no second hidden unbounded allocation. |

Capture format, header/footer, record kinds, loss, truncation and visible offline publication retain the complete base contracts. Lost/truncated capture is incomplete wire evidence. JSON names a public provider binding; it does not load credentials or an opaque provider implementation.

## UDP endpoint fields

| Field | Type and default | Domain and meaning |
|---|---|---|
| `max_udp_datagram_bytes` | uint32; 1472 | 16..65507 for IPv4 or 16..65527 for IPv6 without jumbograms. Interface MTU is not an unconditional capacity cap; allow system IP fragmentation and report actual I/O/path errors. |
| `udp_bundle_delay_ns` | uint64; 1000000 | Zero seals at the end of the current command batch. |
| `max_bundle_messages` | uint16; 64 | Positive count of complete messages. |
| `max_segment_payload_bytes` | uint32; 1392 | Actual selected TP segment maximum, subject to aligned nonfinal capacity and source geometry. |
| `rx_timeout_ns` | uint64; 1000000000 | Positive; actual strategy-specific accepted-segment and expiry semantics apply. |
| `changed_overlap_reject` | bool; false | Explicit FO optional changed-overlap cancellation. It does not replace mandatory overwrite when disabled. |

First check that the effective TP datagram can hold20 bytes. For nonfinal TP payload use `floor(min(configuredMax, effectiveUDPbytes-20)/16)*16` with checked arithmetic; at least sixteen bytes must fit. A 1392-byte segment requires at least 1412-byte datagram capacity. Use the configured/family-limited capacity, not a forced interface-MTU cap. Reject keys that are inapplicable to the selected family/transport. Whole-frame FIFO, due time, ownership and actual send facts retain their existing contracts.

## Method detail and notification fields

`MethodConfig.detailed_errors` is a vector of the exact DetailedErrorSpec defined in the v1.3 error contract, default empty. Both JSON and Native entries use `application_error` and an owning, exact schema-name reference. Existing `methodResponse` is the detailed-error schema role. No new role or C enum is introduced.

`ProvidedServiceConfig.notification_session_handling` is an owning string, default `INACTIVE`, accepting exactly `INACTIVE` / `ACTIVE`. The actual flow key and frame-commit rule are specified in the v1.3 contract. A requested service does not configure the remote sender's mode.

## E2E and early validation

The fourteen pure-library profiles and actual Native network domains are listed in `09_E2E网络绑定能力.md`. A pure/offline P02 declaration remains valid. Its Native normal-region binding is rejected before publication/Protect because source Offset zero overlaps the eight-byte SOME/IP tail. Preserve the source algorithm, pointer origin and Offset domain. Evaluate P01 by its active positions. Other profiles still need their actual source/host geometry, metadata and resource checks. Use existing diagnostics and enums.

STATIC multicast field-initial `initial_unicast`, schema/context default alignment and Struct member identity follow their complete current documents. Validate before the specified registration/output commitment. A successful single-node configuration check does not prove a remote listener or receipt.


## Role SM and endpoint provider name

An actual event/field SM use requires a complete legal state_machine object; role defaultON does not invent windows/thresholds. RPC defaultsOFF and a complete explicit object enables its use. Provided objects must remain valid even when disable_check skips Check/SM. Pure/offline operations retain their explicit Init/operation contracts. See 21_状态机角色与安全提供者名称.md.

EndpointConfig.security_provider is an owning std::string defaultempty. For requires_security=true, JSON must explicitly give a nonempty exact security.providers[].name; before start the caller must bind the real same-name shared_ptr provider through the existing API. For requires_security=false, JSON forbids the key while the Native member must be empty. Missing/duplicate/unknown names or missing actual binding fail at their decidable config/create/start phase before sockets/availability. No implementation/credentials/certificates are loaded by JSON. Real provider gates remain.
