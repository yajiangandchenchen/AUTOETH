# Shared customer contract: HALF_CYCLE processing-time selection

When an eligible Find event is actually processed in MAIN with Unicast Flag one, compute the HALF_CYCLE selector from that processing time and the already committed current-epoch actual complete Offer send fact. Freeze the unicast/multicast destination then. RRD determines logical due only.

At due recheck generation, MAIN and request qualification; cancel invalid work. A new actual Offer while waiting does not recompute this scheduled selector. Owned datagram destination stays stable across EAGAIN. Actual final sending updates lastOfferTime without resetting periodic/repetition due or count.

Positive C, ceil(C/2), BASIC default, Flag0 ignore, no-actual-Offer fallback, existing RRD guards/exemptions and actual TTL rules remain unchanged. This is an explicit LOCAL timing interpretation, not an official source erratum.

Record event processing, queue ownership, POSIX acceptance and peer receipt as separate facts. This document fixes observable behavior and does not claim execution.
