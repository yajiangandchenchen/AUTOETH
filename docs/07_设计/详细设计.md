## 1. 设计目标与不变量

### 1.1 设计目标

1. 单一生产实现：Native 与 Classic 共用同一套编解码、TP、SD、E2E 引擎，Classic 只是"源 C 类型 ↔ Native 引擎"的薄适配层（R9.1、〔03#91〕）。
2. 纯函数优先：`autoeth_e2e`、`autoeth_core` 中的编解码/CRC/TP/SD raw 均可无网络、无线程单测，便于满足覆盖率要求（R0.4.7）。
3. 失败原子性：所有公开操作失败时输出不变，副作用边界明确（R2.5、R8.1、R8.13、R9.15）。
4. 证据可分离：本地构建帧、内核写、对端执行是三份不同事实，设计上分层记录（R12.1）。

### 1.2 全局不变量（编码约束）

| 不变量 | 说明 |
|---|---|
| INV-1 | 公开 C 头只用 C99 语法，不含 C++ 关键字、模板、容器、异常；C++ 侧通过 `extern "C"` 块包含。 |
| INV-2 | 任何"非法但可判定的输入"在进入下一个状态机前被拒绝，且被拒操作不改变输出对象（out 参数保持原值）。 |
| INV-3 | 所有长度/偏移运算走 checked 助手（`add_checked`、`mul_checked`、`sub_checked`），溢出即返回对应错误，不回绕。 |
| INV-4 | 时间只使用单调时钟 `uint64_t` ns；不做墙钟换算。 |
| INV-5 | 线程模型：每个 `Runtime` 一个 IO/定时 owner 线程；回调在 owner 线程调用；不跨线程共享可变注册表（R8.4、R8.14）。 |
| INV-6 | 所有"可失败但非 noexcept 路径"（如内存分配）在公开边界被捕获并转为 Status/CodecResult。 |
| INV-7 | Classic 面绝不另建 SD/TP 算法；所有状态推进由同一引擎驱动（R9.2）。 |

## 4. 核心数据模型

### 4.1 基础类型（`autoeth/types.hpp`）

```cpp
struct ByteView { const uint8_t* data; size_t size; };          // R2.1 / 〔03#11〕
struct MutableByteView { uint8_t* data; size_t size; };
struct DurationNs { uint64_t value; };
struct MonotonicNs { uint64_t value; };
```

约束：
- `ByteView{nullptr, n>0}` 一律 `NullRange`（R2.27、〔03#7〕）。
- `DurationNs` 加法/乘法走 checked，超限报 `LengthOverflow`（INV-3）。

### 4.2 Status / Errc

```cpp
struct Status {                                       // R0.3.3
  uint16_t module;   // Module 枚举值
  uint32_t typed_code;  // Errc 值
  uint64_t byte_offset;
  uint32_t detail;      // 仅 CodecCode
  int32_t native_errno; // 真实 errno，否则 0
};
```

- 构造助手：`status_ok()`、`status_err(Module, Errc)`、`status_codec(Errc, const CodecResult&)`。
- `status_codec` 只把 `code` 放进 `detail`、`byteOffset` 放进 `byte_offset`；`nodeId/dataId` 丢弃（R0.3.4）。

### 4.3 CodecResult

```cpp
struct CodecResult {                                  // R2.27 / 〔07#7-10〕
  CodecCode code;    // uint16_t 表示
  uint64_t byteOffset;
  uint32_t nodeId;
  uint16_t dataId;
};
```

成功一律 `{OK,0,0,0}`（R2.10）。

### 4.4 Value 与编译后 schema

`Value` 直接按公开字段实现（R2.1），不另加隐式字段。
`CompiledSchema` 为不可变树：`shared_ptr<const CompiledNode>`，节点缓存 `memberCount`、`fixedWireWidth`、`hasLengthPrefix`、`defaultAlignmentBits`，由 `compile_codec_schema` 一次性算好（R2.29）。

## 5. 配置加载子系统

### 5.1 分层

```
bytes -> Utf8JsonTokenizer -> JsonDom -> KeyTable(去重检测) -> FieldMapper -> 校验链 -> RuntimeConfig
```

| 层 | 职责 | 失败码 |
|---|---|---|
| Tokenizer | 严格 UTF-8 + JSON 语法；记录每个 token 的字节偏移 | UTF8 错误 → Type4（`R1.1`） |
| KeyTable | 对象内重复键检测（保留首次出现的偏移） | DuplicateKey1 |
| FieldMapper | 把 DOM 映射为强类型字段；只认已知键 | UnknownKey2 / Type4 |
| 校验链 | 按固定顺序逐段校验 | Range5/Reference6/Cycle7/Role8/Unsupported9/Depth10/Count11/ProfileGeometry12/Context13 |
| 资源准入 | 在生成 Runtime 前统计节点/深度/预算 | Resource14 |

### 5.2 关键实现要点

- **整数精确解析**：使用自写十进制/十六进制解析，不经过 `strtod`（R1.1）。
- **深度限制**：Tokenzier 维护显式栈深度并按 `max_schema_depth` 截断（R1.6）。
- **诊断输出**：`ConfigDiagnostic` 只在失败时填充；`file` 为配置所引用文件的真实名，`json_path` 为 `$.schemas[0].root` 形式；构造失败则 `path_complete=false`（R1.4）。
- **校验顺序**为硬编码流水线，不允许短路优化，保证错误码可复现（R1.2）。
- **相对路径解析**：`load_runtime_config` 传入 `base_directory`；每次 `{file:...}` 与 `base_directory` 拼接并归一化（R1.5）。

### 5.3 Schema 编译

- `compile_codec_schema` 内部复用同一 `CompiledNode` 构建器。
- 环检测使用三色标记，错误定位到首次发现的成员（R2.29）。
- 默认值在节点构建末尾统一校验并缓存为 `Value` 快照（R2.3、R2.18）。

## 6. 编解码子系统

### 6.1 接口分层

```
public: measure_payload / encode_payload / decode_payload / compile_codec_schema / Text 四函数
internal: Cursor(encode/decode) / Preflight(rules) / NodeVisitor
```

`Cursor` 统一提供 `read_u(n, endian)`、`write_u(n, endian, v)`、`take_prefix(width)`，所有偏移增量走 checked（INV-3）。

### 6.2 处理流程

**encode**：`preflight(value, node)` → 计算长度 → 与 `MutableByteView.size` 比较 → 逐节点写 → 成功写 `written`。
- 前置失败（ValueType/ValueRange/InvalidText/LengthOverflow）在锚定 O 处返回并保留原 `written`（R2.28）。
- 容量不足返回 OutputCapacity12，O 为 root（R2.28）。

**decode**：`校验 LayoutContext 一致` → 按节点规则读 → 构造临时 Value → 全部成功才 `out = std::move(tmp)`、写 `consumed`。
- 错误定位按 14 号表逐类实现：长度前缀越界→ParentBounds7（前缀首字节）；截断→ParentBounds7（parentEnd）；UnknownTag→KnownWireType9（tag 首字节）；重复已知 tag→DuplicateKnownDataId8（第二次 tag 首字节）；缺必需→MissingRequired10（parentEnd）；未知 union selector→UnknownUnionSelector11（selector 首字节）；文本错误→InvalidText5（非法序列起始/线 extent 起点/extent 终点）（R2.28）。

### 6.3 结构与数组

- Struct：按 `MemberSpec` 声明序遍历，维护 `items/member_ids/member_present` 三向量同步写入；重复 node 不合并（R2.2、R2.31）。
- 完整缺失且具默认的必需成员：塞默认值并置 present=1（R2.3）。
- 固定/动态数组：固定用 `fixedCount` 且元素宽已知，动态用 `maxReceiveCount`；完整多余元素跳过计数器推进，部分元素一律报错，不做默认拼接（R2.18、R2.20）。

### 6.4 Union

```
if (!tagged && hasOuterPrefix) 先读长度
O_sel = 当前位置
if (selector 不完整) -> ParentBounds7(parentEnd)
if (selector == 0)  { if (dataExtent != 0) -> ValueRange4(sel+1) ; 空变体 }
else if (未配置)     -> UnknownUnionSelector11(O_sel)
else                -> 解释变体
```

- `dataExtent = declaredDataLength`（无前缀时由根/父显式给出），排除 selector 与自身前缀；tagged 变体的外层长度含 selector，不得二次加前缀（R2.22、R2.23）。
- 无长度 Union 的"空/下一字段位置"歧义在 schema 编译阶段拒绝（R2.19）。

### 6.5 Text / UTF

- `Text` 内容层严格 UTF-8 校验器（`valid_utf8_strict`），逐码元检查 overlong/代理/超界/5-6 字节（R2.16）。
- 线 BOM（UTF-8：`EF BB BF`；UTF-16：按负载端序）与内容前导 U+FEFF 分开处理（R2.15）。
- `normalize_classic_utf8/utf16` 依据 Classic 的容量/有效单元语义，去除"一个"结构前导 BOM 并严格校验；错误定位见 14 号表（R2.28）。
- UTF-16 末尾奇字节忽略只发生在父/线最大界检查之后（R2.17）。

### 6.6 对齐

- 每个节点写入前按"节点对齐 → TLV 静态宽度对齐 → Struct 成员对齐"次序填充；`LayoutContext` 只决定最初偏移 O，不覆盖 wire 布局（R2.8）。
- `default_alignment_bits` 的"合法但不等"必须在输出前失败，检查位于 encode/decode 入口第一行（R2.8）。

## 7. 线协议与校验

### 7.1 组帧

- 16B 头字段按网络字节序（SOME/IP 规范）；`length` 从 RequestID 起计（R3.1、R3.2）。
- `decode_header` 返回 `frame_bytes`，用于后续分帧；短于 16B 返回 `NeedMore`。

### 7.2 validate_message

```
1 protocol_version != 1                 -> ProtocolVersion
2 service_id == 0/FFFE/FFFF             -> UnknownService
3 interface_version 不匹配              -> InterfaceVersion
4 method 未声明                         -> UnknownMethod
5 类型/usupported/configured 不匹配      -> MessageType
6 Type/ReturnCode 对非法                -> MessageType (R3.4)
7 correlation 不匹配                    -> UnknownRequest
8 payload/E2E                           -> PayloadMalformed / RemoteProtocol
```

- 回复资格、类型/角色一致性与错误回环抑制分别实现为独立谓词（R3.5、R3.6）。
- 0x0A 错误回复由 `make_error_reply(header)` 构造，复制 MessageID/RequestID，protocol 用 1（R3.5）。

## 8. TP 子系统

### 8.1 统一接口

```cpp
Status segment(const Message&, const TpTxConfig&, SegmentSink&);
Status TpReceiver::accept(const Peer&, ByteView wire, uint64_t now_ns, ReceiveOutcome&);
void   TpReceiver::expire(uint64_t now_ns, ExpirySink&);
void   TpReceiver::reset(ResetReason);
```

`TpRx` 内部按 `Strategy` 分派到 `FoReassembler` 与 `CpReassembler`，两者**独立建模**（R5.1，不混用规则）。

### 8.2 分段预算

```cpp
D = min(cfg.max_datagram_bytes, family_limit);   // family_limit: IPv4 65507 / IPv6 65527
if (D < 20) reject;
rawCap    = min(cfg.max_segment_payload_bytes, D - 20);
nonfinal  = (rawCap / 16) * 16;
if (nonfinal < 16) reject;
```

末段允许剩余非 16 倍数（R5.3）。

### 8.3 FO 重组状态

```cpp
struct FoAssembly {
  uint64_t generation;     // 计时代数
  uint32_t final_end;      // 首 M0 固定
  std::vector<uint8_t> buf;
  std::bitset/区间表 covered;   // 记录已覆盖区间，区分"空锚"与"非空覆盖"
  uint8_t last_return_code;     // 最后实际接受段
  bool has_started;
  uint64_t deadline;
};
```

| 事件 | 处理 |
|---|---|
| M0 且已存在装配 | 冲突终点/覆盖范围/零锚点约束 → cancel（R5.6） |
| 范围内段 | 覆盖写入；`changed_overlap_reject` 决定变动重叠是否取消（R5.2） |
| 缺口 | 取消（R5.2） |
| 每段被接受 | 刷新 inactivity deadline（R5.4） |
| `now>=deadline` | 先于同时刻入站处理（R5.5） |
| 超容量 | 取消并留 discard marker 至 newSession/原 deadline（R5.7） |
| 完成 | 移除装配、输出 Message、ReturnCode 取最后接受段（R5.7、R5.8） |

### 8.4 CP 重组

保留 zero-first/连续/restart0、8B 上部头尾比较、清 TP 标志前头比较（R5.12）。CP 与 FO 的退出/错误行为各自独立实现，不共享计数器（R6.4 同理）。

### 8.5 TpReceiver 输出分类

`ReceiveOutcome` 明确 `Accepted / Ignored / Cancelled` 三态 + 可选完成 Message + 诊断；部分接受不产出 Message（R5.9）。`expire` 按每次真实取消各上报一次；`reset` 只作用于本接收器（R5.10）。

---

### 8.6 丢弃标记（discard marker）

超容量或被动取消后，为原会话保留一个有界丢弃标记：

```
struct DiscardMarker { uint32_t session; uint64_t expiry_ns; };
```

- 占用一个 `max_tp_rx_contexts` 槽位（与装配隔离计数，R1.12）。
- 生命周期：`newSession` 到达或到达原 deadline（`now>=expiry_ns`）时释放；不得二次取消。
- 释放前对该会话的迟到分段一律 `Ignored`，不产出 Message、不刷新任何计时。

## 9. E2E 子系统

### 9.1 目录与命名

```
src/e2e/profiles/   p01.c p02.c p04.c p04m.c p05.c p06.c p07.c p07m.c p08.c p08m.c p11.c p22.c p44.c p44m.c
src/e2e/sm/         sm.c
src/e2e/wide/       p08_wide.cpp p08m_wide.cpp
src/e2e/crc/        复用 core/crc
```

- 14 个 profile **各自独立源文件**，禁止抽象为"万能 profile 表"（R6.4；对应你此前强调的"不混用状态机与计数规则"）。
- 每个 profile 提供 `Init / Protect / Check` 或 `Source/Sink` 函数，与 C 名一一对应；Native 包装仅做类型边界与 checked 变换。

### 9.2 计数器与模域

| profile | 首值 | 模 |
|---|---|---|
| 02 | 预增，首个 1 | 16 |
| 01 / 11 | 后增，首个 0 | 15 |
| 22 | 后增 | 16 |
| 其他 | 后增 | 实际宽度 |

此表直接实现 R6.5，禁止把 P22 的模 16 套到 P11、把 P05 隐式 DataID 套到 P06（R6.4）。

### 9.3 宽域 P08/P08m

- `P08ConfigWide`、`P08mConfigWide` 字段序：`data_id:uint32_t; max_data_length_bits:uint64_t; max_delta_counter:uint32_t; min_data_length_bits:uint64_t; offset_bits:uint64_t`（〔03#114〕）。
- `to_classic_*_config`：所有 bit 字段检查能否装入 uint32，失败 `UNREPRESENTABLE_CLASSIC_BIT_LENGTH` 且 out 不变（R6.6）。

### 9.4 SM

- `sm_check` 依据 `SmConfig` 与窗口状态推进，VALID/INVALID 只由真实窗口计数决定（R6.9，禁止伪造 VALID）。
- `from_classic_sm_config` 映射 `ClearToInvalid`，`combined_no_data_init_count=false`（R6.8）。

### 9.5 网络绑定

```
E2eChannel (config)
  ├─ ChannelGeometry   解析 profile 类别（normal / method / source-sink）
  ├─ CounterSource     事务计数器来源（客户端 seed request-1，服务器 sink 独立）
  └─ RegionCheck       验证受保护区在 8B 尾之后且不越界
```

- 配置期先跑 `RegionCheck`；P02 的 normal 绑定直接返回既有 `Unsupported`/`ProfileGeometry` 诊断，不提交（R6.12）。
- 方法 profile 的 Offset 上界按 profile 单独实现：04m 128bit、07m 192、08m 160、44m 128（R6.13）。
- Sink 发布 SourceID 用独立 `PublishSourceId(uint32)` 函数，仅在 CRC/DataID/type/result/length 全过时才调用（R6.15）。

### 9.6 保护错误路径

| 情形 | 线行为 |
|---|---|
| 受保护路径错误且元数据可信 | RESPONSE 0x80 + E2E 头 + 空应用参数（R6.21） |
| 可信元数据不可用 | 丢弃，不回未保护（R6.21、R3.6） |
| 详细应用错误 | ERROR 0x81 + code+0x1F + detailed schema（R6.23、R11.4） |

## 10. SD 子系统

### 10.1 raw 编解码

`decode_sd_message` 严格按结构解析 Message + Entries + Options，保留原字节与顺序；能力记录保留大小写/重复/原始二进制（R7.4）。查找键比较使用 ASCII 小写化后的视图，按首个 `=` 拆分（R7.4）。

### 10.2 接收端流水线

```
Stage 0  ExtentScan        全消息/entries/options extent 与 run 安全性（失败 -> 全消息失败，无半提交）
Stage 1  EntryClassify     条目类型与角色（Find/Offer/Subscribe/StopSubscribe/Ack/Nack/Unknown）
Stage 2  OptionRefCheck    引用选项合法性 + 冗余副本/未知 DF1/不需要选项忽略；保留 raw 诊断
Stage 3  OptionSemantics   类型/数量/族/L4/地址/端口/冲突 + run 越界 + Config 特例
Stage 4  Engine            状态提交 / ACK / NACK / failedACK / ignore
Stage 5  FieldInitial      按 R7.25 决定初值目的地
```

逐表实现：
- 端口 0 → `is_actionable_endpoint()` 检查；不可行动按角色执行 ignore/NACK/failedACK（R7.11）。
- Reserved12/Counter4 在 ACK 与错误 NACK 中逐位回显（R7.10）。
- 消息级 SD Endpoint 24/26 的覆盖判定独立于条目引用（R7.13、R7.14）。
- run 越界在完全可定位时归条目错误；不可定位才全消息失败（R7.17）。

### 10.3 状态引擎

```
SdEngine
 ├─ ServerStates   (per service): DOWN → INITIAL_WAIT → REPEAT → MAIN
 ├─ ClientStates   (per query):  DOWN → SEARCHING → REQUESTED → AVAILABLE
 ├─ SubscribeStates(per client×group)
 ├─ Timers         (offer repetition / cyclic / find / ttl / retry)
 └─ ActionBatch    有界输出，状态转移前预留容量
```

- 定时优先级：控制失效 → 取消处理 → 过期 → 入站 → 调度动作（R8.5 同构）。
- HALF_CYCLE 选择器在处理时刻冻结（R7.27、〔20#5〕）。
- `lastOfferTime` 只在实际完整 SD 数据报 POSIX 接受时更新（R7.27）。

#### 10.3.1 ActionBatch 预留顺序

```
1. 依据当前状态与事件计算"最坏情形动作数"（SendSD/RoutingChange/ConnectionRequest/
   CurrentStateChange/FieldInitial/Diagnostic 各自的条数上限）
2. 以该上限向有界 ActionBatch 预留容量
3. 预留成功后才允许修改引擎状态
4. 按顺序填充动作
```

- 第 2 步失败返回 `Resource`，状态保持不变（不允许"半个订阅/半个 Offer"，R7.29）。
- 第 4 步填充不允许再申请容量。

### 10.4 选择算法

```
eligible = filter(service/version/ttl/endpoint/client)
if (query.instance is Exact) return first eligible
best_tier = min(explicit priority)   // 缺失 priority 视为低于 65535 的无穷大且不进入显式层
if (tier has all-zero weights) -> LOCAL uniform within tier
else -> uint64 sum, draw in [0,sum), half-open cumulative
```

sum 的加法走 checked；`RandomDraw` 由调用方注入，测试用确定性实现（R7.19、〔03#87〕）。

## 11. Runtime 子系统

### 11.1 线程与事件循环

```
Runtime
 ├─ owner thread: epoll/kqueue-free (poll) loop
 ├─ control queue (MPSC, 有界): 所有公开 API 从任意线程投递
 ├─ timer heap: 单调 ns
 └─ registries (仅 owner 线程可写)
```

- 公开方法只做"校验 + 拷贝 + 入队"，不做 IO（R8.4、〔02#45〕）。
- 回调在 owner 线程调用；`request_stop` 置标志并唤醒，不 join（R8.14）。

### 11.2 句柄与代数

```cpp
struct HandleAllocator {          // 进程级，全局递增
  uint32_t next_slot;
  uint64_t next_generation;       // 永不回绕
};
```

- 每个句柄族（Service/Request/Subscription/Call）独立槽表；释放后槽可复用但代数新（R8.3）。
- 代数耗尽 → `CounterExhausted`，在准入/Protect 之前（R8.3）。

### 11.3 调用生命周期

```
call() → 校验 MethodRef/Value → 指派 Session → 预分配资源 → 入队 → 返回 CallHandle
owner:
  admission → queue → （可选）E2E Protect → 发送 → WAITING
  完成源：response 到达 / timeout(now>=D) / cancel / 传输中止
  终结：completion_snapshot 可见，Callback 调用一次
```

- 顺序严格遵循 R8.5 / R8.6。
- 部分 TCP 取消中止整个连接，兄弟调用标记 TIMEOUT 或 ConnectionAbortedByPartialCancel（R8.7）。

### 11.4 资源账本

```
Ledger
 ├─ owned_payload_bytes  (R1.18)
 ├─ sockets / memberships / tp_rx_contexts / e2e_rx_contexts
 └─ per-admission reservation (RAII 归还)
```

- 准入前 `Reserve()`，失败返回 Resource 且不改变任何注册表（R1.17）。
- 归还跟随真实最后拥有者（R1.18）。

### 11.5 诊断与快照

- 诊断环固定容量，溢出覆盖最旧并 `lostRecords++`（R8.12）。
- `snapshot()` 复制当前不可变视图；复制即持有引用计数 token（R8.12）。


诊断记录字段（与 R8.12 对齐）：

```cpp
struct DiagnosticRecord {
  uint64_t sequence;          // 单调递增
  uint64_t monotonic_ns;
  bool     has_operation;     // 是否关联到具体调用/操作
  uint32_t operation_slot;    // has_operation=true 时有效
  uint64_t operation_generation;
  bool     has_codec_result;  // 完整 CodecResult 仅在被保留时存在
  CodecResult codec_result;
  Status   status;            // 窄错误，始终可用
};
```

- 溢出覆盖最旧记录并递增 `lostRecords`；被覆盖的 `codec_result` 不保证可再取回（R0.3.4）。

### 11.6 通知 Session

```cpp
struct NotificationFlowKey { interface; service; instance; major; event; transport; peer_or_mcast; };
```

- INACTIVE 时 Session 恒 0；ACTIVE 时每 flow 独立 `nextSession` 从 1 起，满回 1（R8.16）。
- 仅在拥有的原始帧成功提交后推进（R8.17）。
- 发送用的 Client ID 恒 0（R8.16）。

## 12. 传输层

### 12.1 Socket 抽象

```cpp
class DatagramSocket;   // UDP，含 sendmmsg/recvmmsg 可选
class StreamSocket;     // TCP，含分帧缓冲
class MulticastReceiver;
```

- 每个 socket 单独设置复用/加入/源选择/hops/loopback；`tcp_no_delay` 只作用于该连接（R4.6、R4.7）。
- 组播接收记录真实来源 (addr, port, ifindex)（R4.8）。

### 12.2 IPv4/IPv6 双族

- 每个接口地址族独立维护 `ServiceKey → relationship` 状态；同一 entry 只用其真实外层族，不混合族端点（〔02#64〕）。
- IPv6 链路本地地址需 scope_id；无 scope 配置则报 Context13（R1.19）。

### 12.3 发送 EAGAIN

- EAGAIN 重试同一拥有帧与同一 Session ID；TP 子段共享 Session（R8.17）。

## 13. Classic C 适配层

### 13.1 结构

```
src/classic_host/
  pdur/     1:1 路由与组
  soad/     soCon 状态、地址、路由、Tp/If 传输
  someip_tp/ CP 状态机（复用 src/core/tp 的 CP 实现，但 C 回调上下文单独维护）
  sd/       C 句柄 ↔ Native ServiceKey 映射、current callbacks
  transformer/ SomeIpXf、E2EXf 的 25 个符号
  diag/     DiagnosticObserver
```

### 13.2 绑定与配置

- `bind()` 在 `Runtime::start()` 前调用；`ClassicHostConfig` 的六个 ConfigPtr 保存到全局单例表（进程内唯一），并做完整字段/计数/引用检查后再 Init（R9.3、R9.4）。
- 初始化顺序强制 PduR → SoAd → SomeIpTp → Sd（R9.2）。

### 13.3 头模式

- `pduHeaderEnabled=TRUE` 的 SoAd 在发送时构造 8B Message-ID/Length 头，长度按实际上层 PDU 重算（R9.13）。
- 上层 SomeIpXf/SomeIpTp 从 8B Request-ID 尾开始；Native 完整 16B 头绝不叠加两个 8B 头（R9.13）。

### 13.4 回调转发

- 同步 PduR 1:1 转发保留原 metadata 与 BufReq 结果（〔03#95〕）。
- 异步 Native 消费在返回前复制 PduInfo（`〔04#131〕`）。
- 所有失败/终结通知对已接受传输只发生一次（`〔04#131〕`）。

### 13.5 transformer 上下文

- 事务句柄 `E2EXf_CSTransactionHandleType{e2eCounter,e2eSourceId}` 与 Native 事务表关联；事件通道不需要 RPC 上下文（R9.15）。
- 无绑定上下文返回 0xFF 且输出不变（R9.15）。

---

### 13.6 DiagnosticObserver 调用时机

- 只在内部状态**已提交完成**之后调用，且必须在本次调用返回调用方之前完成。
- 传入不可变拥有型诊断；观察者不可重入引擎、不可调用任何 `*_MainFunction`。
- 观察者异常在边界捕获并转为本地诊断，不得回滚已提交状态（R9.16）。

## 14. 程序设计

### 14.1 autoethd

```
main
 ├─ 解析参数（--config --dataset --dataset-format --event-period-ns）
 ├─ load_runtime_config + 校验
 ├─ 读取数据集（完整拥有 + SHA-256）→ 失败则 exit
 ├─ create_runtime / offer_service / set_available
 ├─ 业务 handler：ReadSnapshot / ReadBulk / ApplyCalibration / RecordCommand
 ├─ 周期事件：VehicleEvent（按 --event-period-ns）
 ├─ 信号：SIGINT/SIGTERM → request_stop → 等待 → stop
 └─ 退出时打印 StopOffer 实际发送结果
```

- 标定提交为"预留 → owner 循环一次提交 revision+1"两阶段（R10.5）。
- 命令环用定长环形数组，覆盖最旧记录（R10.6）。

### 14.2 autoeth-client

- 每个子命令封装为 `Command` 对象：`prepare → validate_descriptor → call → format_result → exit_code`（R10.8）。
- 退出码映射表集中在 `ExitCodes`，由 `Status/CompletionSnapshot` 决定（R10.10）。

### 14.3 autoethctl

- 离线命令独立于 Runtime；`e2e-protect/check` 使用真实库 Init/Protect/Check（R10.13）。
- 结果目录发布：`<out>.tmp-<pid>-<rand>` 写入 → `rename` 到目标（R10.14）。
- 采集解析器逐行解析，遇内部畸形立即停止并报偏移（R10.16）。

---

采集 `record_kind` 与事实层级映射（R10.16、R12.1）：

| record_kind | 事实层级 | 是否可作为网络证据 |
|---|---|---|
| `FrameBuilt` | 本地构建，尚未写内核 | 否 |
| `KernelWrite` | 内核写入返回 | 否（非对端接收） |
| `KernelDatagramAccepted` | 内核接受数据报 | 是（本端） |
| `RxChunk` / `RxFrame` | 本端接收 | 是 |
| `Terminal` | 操作终结（含超时/取消） | 否 |
| `Loss` | 采集环丢失 | 否 |

## 19. 已确认的设计取舍

| 编号 | 取舍 | 影响范围 |
|---|---|---|
| D-1 | 公开头**手写**，逐条对齐 `公开接口清单.tsv`（Native 57 / Classic 153 / Configured 25）；评审时以 TSV 为核对清单，不自造符号。 | S0、S9、R0.1.5 |
| D-2 | 单元测试使用**自研轻量断言**（仅标准库 + POSIX，CTest 驱动），不引入 Catch2/GoogleTest。 | 全部阶段、R0.4.1 |
| D-3 | Classic Main 与 Native owner **合并为同一循环**：`SoAd_MainFunction`/`SomeIpTp_MainFunction`/`Sd_MainFunction`/`PduR_MainFunction` 由 owner 循环按 `main_period_ns` 统一调用，严格单 owner，禁止外部并发驱动。 | S9、R9.2、INV-5 |

D-3 的细化约束：

- 源 C 的 `*_MainFunction` 入口仍按原签名导出，但实现内部只接受 owner 线程调用：非 owner 线程调用返回诊断并丢弃本次推进（不新增公开枚举）。
- 初始化顺序 PduR → SoAd → SomeIpTp → Sd 在 `bind()` 后的 owner 首次调度时按序执行，在此之前不发布任何可用性。
- Classic 的 `IfTxConfirmation` 只在 owner 循环的"发送/回调阶段"内产生，保证"一次确认"语义。
