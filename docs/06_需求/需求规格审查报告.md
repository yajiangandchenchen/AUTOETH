## 4. 需你裁决的合同口径（3 项）

这三项不是文档错误，而是原件/合同之间存在**允许两种读法**的地方，需求规格只能按其中一种写死：

### C-1 TP 非末段上界的"最终段"是否也受结构约束

- 现状：R5.3 写"末段可含剩余非 16 倍数"，符合 〔19#12〕。
- 但 〔19#10〕还写了"respecting the configured upper bound and actual datagram capacity"。
- 两种读法：(a) 末段只受配置上界与容量；(b) 末段还受"不得大于非末段"约束。
- **我采用 (a)**，因为原文只对 M=1 段提出 16 字节对齐要求。

### C-2 P01 legacy CheckInit 的 `WaitForFirstData` 初值

- 〔02#27〕写 `WaitForFirstTRUE`（缺一个字符），〔05#84〕写 `WaitForFirstDataTRUE`。
- 两种读法：(a) 按 05 号展开为 `WaitForFirstData=TRUE`；(b) 严格按 02 号字面。
- **我采用 (a)**，因为 05 号是更具体的枚举化表述。

### C-3 详细错误 ERROR81 时 `application_error` 为 0 的处理

- 〔13#27-30〕只写"非零 code 映射"，未写"配置了 detailed_errors 但 code 为 0"的情形。
- 两种读法：(a) code 0 一律走成功 RESPONSE0x80（现状 R11.4 第三条）；(b) 允许 0 走详细错误。
- **我采用 (a)**，与"码 0 = 现有成功 RESPONSE"一致。
